# LiteTok — облегчённый Android-клиент TikTok для слабых устройств

## Что это

LiteTok — нативное Android-приложение (Java, без AndroidX и тяжёлых
библиотек), которое оборачивает мобильную веб-версию TikTok
(`https://www.tiktok.com/`) в оптимизированный `WebView`. Это осознанный
выбор архитектуры: **публичного API для сторонних клиентов TikTok не
существует** — единственный легальный и стабильный способ получить весь
функционал (ленту, лайки, комментарии, загрузку видео, поиск, профиль,
директ) — использовать их же официальный веб-интерфейс, но в
контролируемой, лёгкой обёртке.

Проект не аффилирован с TikTok/ByteDance, не использует их товарные знаки
в оформлении и не собирает данные пользователя — вся авторизация и весь
контент идут напрямую между устройством и `tiktok.com`.

## Функциональность

- Полный функционал мобильного веб-TikTok: лента, лайки, комментарии,
  загрузка видео, поиск, профиль, сообщения — всё, что отдаёт сам сайт
  мобильному Chrome.
- **Авторизация**: логин/регистрация через собственные формы TikTok внутри
  WebView; сессия и cookies сохраняются между запусками (не нужно логиниться
  каждый раз). OAuth-вход через Google/Facebook/Apple/X принудительно
  открывается в системном браузере, так как эти провайдеры блокируют вход
  из встроенных WebView.
- Загрузка видео из галереи в TikTok (`<input type=file>` → системный
  выбор файла) и съёмка с камеры/микрофона (`getUserMedia`) с нативным
  запросом рантайм-разрешений.
- Скачивание файлов через `DownloadManager` с передачей cookies и
  User-Agent.
- Обработка отсутствия сети (офлайн-экран с повтором), навигация назад/
  вперёд, двойное нажатие «назад» для выхода.
- Настройки: **режим для слабых устройств** (заголовок `Save-Data`,
  отключение CSS-анимаций на странице), переключатель мобильная/десктопная
  версия сайта, масштаб текста, очистка cookies/кэша (выход из аккаунта).

## Почему это не WebView "в лоб", а именно версия для слабых устройств

- Ни одной сторонней библиотеки и ни одного тяжёлого экрана: один
  `Activity` + WebView, минимум байткода → APK около 40–50 КБ.
- `minSdkVersion 21`, `targetSdkVersion 23` (Android 5.0–6.0) — уровень,
  типичный для бюджетных устройств, которые обычно и просят "версию для
  слабых телефонов".
- `WebView.onPause()/pauseTimers()` при уходе в фон — не грузит CPU/сеть,
  когда приложение свёрнуто.
- Режим "Save-Data" и отключение CSS-переходов уменьшают трафик и нагрузку
  на GPU на слабом железе.
- Никакого Compose/RecyclerView/ExoPlayer — воспроизведение видео и вся
  разметка идут средствами системного WebView (Chromium), который на
  реальном устройстве уже оптимизирован и обновляется отдельно от
  приложения через Google Play.

## Сборка

APK собран и подписан прямо в этой среде (см. `litetok-debug.apk`,
приложен отдельным файлом) — **полностью офлайн**, пакетами Debian/Ubuntu
(`aapt`, `aidl`, `apksigner`, `zipalign`, `android-sdk-platform-23`,
`dalvik-exchange`), без обращения к `dl.google.com` (он недоступен из
этого окружения по сетевой политике — Android SDK Manager и Gradle Android
Plugin используют именно его). Это тот же байт-в-байт код, что лежит в
`app/src/main/java`, просто собранный классическим тулчейном
aapt → javac → dx → zipalign → apksigner вместо Gradle.

### Пересобрать здесь же (офлайн, тем же способом)

```bash
sudo apt-get install -y aapt aidl apksigner zipalign \
    android-sdk-platform-23 dalvik-exchange
./build.sh
# результат: ./litetok-debug.apk
```

### Собрать через Android Studio / Gradle (рекомендуется для дальнейшей разработки)

В проекте есть обычная структура Gradle-проекта (`settings.gradle`,
`build.gradle`, `app/build.gradle`). Откройте папку `android-tiktok-client`
в Android Studio (или выполните `./gradlew assembleDebug` при наличии
интернета и Android SDK) — так же можно поднять `compileSdkVersion` до
более новой версии, подключить AndroidX и т.д., если понадобится
развивать проект дальше.

### Установка на устройство

```bash
adb install -r litetok-debug.apk
```

## Ограничения, о которых стоит знать

- Это обёртка над сайтом, а не переписанный "родной" клиент — некоторые
  вещи (пуш-уведомления, оффлайн-кэш видео, продвинутая рекомендательная
  лента приложения) на веб-версии TikTok работают ограниченно или не
  работают вовсе — это ограничение самого сайта, а не приложения.
- TikTok может показывать капчу/защиту от ботов чаще, чем в официальном
  приложении, так как видит нестандартный User-Agent/WebView.
- В этой среде нет Android-эмулятора (недоступен по той же причине — сборка
  system-image тоже идёт через `dl.google.com`), поэтому финальная сборка
  проверена статически: валидный подписанный APK (`apksigner verify`
  проходит v1/v2/v3 схемы), корректный AndroidManifest и байткод
  (`aapt dump badging`, `dexdump`), но не прогонялась вручную на реальном
  экране. Рекомендуется проверить на реальном устройстве/эмуляторе перед
  публикацией.
