# QMods Telegram Bot

Telegram-бот для сервиса QMods, работающий как дополнительный канал
управления существующим личным кабинетом **qmods.ru/mod**. Бот не заводит
отдельную базу пользователей/подписок/устройств — он читает и изменяет те
же данные, что и кабинет, через два защищённых JSON API на самом сайте.

Хостинг бота — **Cloudflare Workers** (не классический PHP-хостинг с cron):
логика бота выполняется как serverless-воркер на TypeScript, а всё
взаимодействие с данными QMods идёт по HTTPS в PHP-эндпоинты сайта.

## Архитектура

```
┌─────────────┐   webhook (HTTPS)   ┌────────────────────────┐   HTTPS + токен   ┌───────────────────────┐
│  Telegram    │ ──────────────────▶ │ Cloudflare Worker      │ ─────────────────▶ │ qmods.ru               │
│  (пользо-    │ ◀────────────────── │ (telegram-bot/worker)  │ ◀───────────────── │ mod/api/bot.php         │
│  ватели)     │   sendMessage       │                         │   JSON             │ mod/admin/bot.php       │
└─────────────┘                     │  D1: состояния диалогов,│                    │ (читают/пишут           │
                                     │  рейт-лимиты, аудит-лог │                    │  data/users.json,       │
                                     │  Cron Trigger: доставка │                    │  data/notifications.json)│
                                     │  отложенных уведомлений │                    └───────────────────────┘
                                     └────────────────────────┘
```

- **`worker/`** — сам бот (Cloudflare Worker, TypeScript). Единственное, что
  нужно задеплоить на Cloudflare.
- **`php-api/`** — дополненные версии двух уже существовавших на сайте
  файлов (`mod/api/bot.php`, `mod/admin/bot.php`) + один новый файл-помощник
  (`mod/includes/bot_notify.php`). Их нужно один раз загрузить на qmods.ru.
  Подробности — в `php-api/INTEGRATION.md`.
- **`API.md`** — полный контракт обоих API (какие запросы делает бот, какие
  ответы ожидает).

Почему так: по условию задачи бот обязан работать поверх существующей
системы пользователей QMods, а не поверх своей копии. Cloudflare Workers не
может напрямую читать файлы/БД на обычном PHP-хостинге, поэтому единственный
безопасный способ — HTTPS API с токеном, который сайт уже частично имел
(`mod/api/bot.php`, `mod/admin/bot.php` существовали и раньше) — этот
проект его дополняет, а не изобретает заново.

## Функционал

**Пользователь:**
- `/start` — приветствие, определение статуса привязки, главное меню.
- `/link` — привязка аккаунта по одноразовому коду из кабинета (код,
  ограниченный по времени и попыткам — генерируется и хранится на стороне
  сайта, как и раньше).
- 👤 Профиль — логин, ID, дата регистрации, уровень, ссылка на скачивание
  APK, форма отзыва.
- ⭐ Подписка — тариф, статус, даты, сколько дней осталось; предупреждение,
  если подписка скоро закончится/уже закончилась.
- 📱 Устройства — просмотр и отвязка с подтверждением.
- 🏆 Достижения — уровень (Новичок/Активный/VIP/Легенда), прогресс до
  следующего, каталог из 13 наград с бонусными днями; синхронизация и
  начисление бонусов происходит прямо в боте, не только на сайте
  (мигрировано из `includes/achievements.php`).
- 🎁 Рефералы — реферальный код и ссылка (генерируется при первом
  обращении), счётчик приглашённых.
- 💳 Оплата — история платежей + кнопка «Продлить» на `qmods.ru/subscribe/`.
- 🔔 Уведомления — личные и общие уведомления, отметка прочитанным.
- 🆘 Поддержка — ссылка на `support.php` + чат сообщества.

**Администратор** (`/admin`, ID в `ADMIN_TELEGRAM_IDS`):
- статистика (пользователи, активные подписки, привязанные Telegram-аккаунты);
- поиск пользователя по логину, карточка со всеми данными;
- продление/снятие подписки, удаление аккаунта (с подтверждением);
- отправка сообщения конкретному пользователю или рассылка всем.

**Push-уведомления** (Cron Trigger раз в 5 минут): оплата, окончание
подписки (уже автоматизировано на сайте, см. `reminders.php`), сообщения
администратора, новости — доставляются даже если пользователь не открывал
бота в момент события.

## Mini App

Кнопка «🖥 Открыть в Mini App» в главном меню открывает `GET /app` —
тот же функционал в виде нативного полноэкранного интерфейса внутри
Telegram: вкладки Профиль (+ скачать APK, отзыв), Подписка, Устройства,
Награды (уровень, прогресс, достижения, рефералы), Оплата, Уведомления, а
для непривязанного аккаунта — экран ввода кода. Тема (тёмная/светлая)
подхватывается автоматически через `--tg-theme-*` CSS-переменные, которые
Telegram сам подставляет.

- Один файл, без сборки и фреймворков (`worker/src/webapp/page.ts`) —
  разметка, стили и JS-логика в одном месте, отдаётся как обычный HTML.
- Бэкенд — один эндпоинт `POST /app/api`, авторизация через Telegram
  `initData` (см. «Безопасность» ниже), логика полностью переиспользует
  `QmodsUserApi` — та же авторизация к `mod/api/bot.php`, что и у чат-бота.
- Работает независимо от чат-версии: можно продолжать пользоваться только
  кнопками, Mini App — альтернативный, а не обязательный интерфейс.
- Требует `WEBAPP_URL` в `wrangler.toml` (полный `https://.../app` URL
  этого же воркера) — если оставить пустым, кнопка просто не показывается.
- Регистрировать домен через @BotFather не нужно — это требование только
  для Login Widget и персистентной Menu Button, а не для `web_app`-кнопок
  в инлайн-клавиатуре, которые использует этот бот.

## Безопасность

- **Webhook**: Telegram шлёт заголовок `X-Telegram-Bot-Api-Secret-Token`
  (задаётся при `setWebhook`), воркер сверяет его константным по времени
  сравнением до разбора апдейта — `src/security.ts`.
- **API-токены**: два независимых bcrypt-хешированных токена
  (пользовательский/админский), сверяются на сайте через `password_verify()`.
  Сами токены — только в секретах воркера (`wrangler secret put`), никогда
  не попадают в код/репозиторий.
- **Рейт-лимит**: код `/link` ограничен на двух уровнях — в воркере (D1,
  6 попыток / 10 мин на чат) и на сайте (`data/bot_link_attempts.json`,
  8 попыток / 15 мин на telegram_id).
- **Mini App**: каждый запрос к `POST /app/api` обязан нести заголовок
  `Authorization: tma <initData>`. `initData` проверяется по официальной
  схеме Telegram (`worker/src/webapp/validate.ts`) — HMAC-SHA256 на секрете,
  производном от `TELEGRAM_BOT_TOKEN`, плюс проверка `auth_date` (не старше
  24 часов, защита от replay). `telegram_id` берётся только из
  провалидированной подписи — Mini App физически не может подставить чужой
  ID в запросе.
- **Права администратора**: единая проверка `isAdmin()` перед любым
  `adm:*`-действием и при обработке текстового ввода в админ-режиме — даже
  если состояние диалога в D1 каким-то образом переживёт потерю прав.
- **Логирование**: действия администратора пишутся в D1
  (`admin_audit_log`) независимо от `data/actions.log` на сайте; ошибки
  воркера видны через `wrangler tail`.
- Входные данные everywhere проходят через типизированные API-клиенты и
  HTML-экранирование (`esc()`) перед вставкой в сообщения — защита от
  инъекции разметки через логин/название тарифа и т.п.

## Установка и деплой

### 1. PHP-часть (qmods.ru)

См. `php-api/INTEGRATION.md` — какие файлы куда положить, как сгенерировать
токены, где (опционально) добавить одну строку для проактивных уведомлений
об оплате.

### 2. Telegram-бот

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. `cd telegram-bot/worker && npm install`
3. `wrangler d1 create qmods-telegram-bot` — скопируйте `database_id` в
   `wrangler.toml`.
4. `npm run db:init` — накатывает `schema.sql` на созданную D1-базу.
5. Секреты:
   ```bash
   wrangler secret put TELEGRAM_BOT_TOKEN
   wrangler secret put TELEGRAM_WEBHOOK_SECRET       # любая случайная строка, напр. `openssl rand -hex 32`
   wrangler secret put QMODS_BOT_API_TOKEN           # токен для mod/api/bot.php
   wrangler secret put QMODS_ADMIN_BOT_API_TOKEN     # токен для mod/admin/bot.php
   ```
6. Проверьте/поправьте `vars` в `wrangler.toml` (`QMODS_API_BASE`,
   `ADMIN_TELEGRAM_IDS` и т.д.).
7. `npm run deploy` — публикует воркер, выводит URL вида
   `https://qmods-telegram-bot.<account>.workers.dev`.
8. Если URL воркера отличается от того, что уже стоит в `WEBAPP_URL` —
   поправьте на `<ваш-URL>/app` и передеплойте, иначе кнопка Mini App не
   покажется в меню.

### 3. Подключение webhook

Самый простой способ — встроенный служебный маршрут воркера:

```
GET https://<worker-url>/setup-webhook?token=<TELEGRAM_WEBHOOK_SECRET>
```

Откройте эту ссылку один раз в браузере (или `curl`) — воркер сам вызовет
`setWebhook` с правильным URL и секретом. Убедиться, что всё подключилось:

```bash
curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"
```

### 4. Cron (доставка отложенных уведомлений)

Уже настроен в `wrangler.toml` (`[triggers] crons = ["*/5 * * * *"]`) —
отдельно ничего запускать не нужно, `wrangler deploy` регистрирует триггер
автоматически. При необходимости поменяйте частоту там же.

## SQL / хранилище данных

qmods.ru хранит пользователей, подписки, устройства и уведомления в
файлах `data/*.json` (см. `includes/bootstrap.php` на сайте) — это
**существующая архитектура**, новых MySQL-таблиц под неё создавать не
нужно и не следует (задача явно требует не плодить отдельную базу).

Единственное новое хранилище — **Cloudflare D1** (`worker/schema.sql`),
и оно принадлежит исключительно боту:

| Таблица | Назначение |
|---|---|
| `bot_state` | Состояние диалога чата (например, «ждём код /link») |
| `rate_limits` | Скользящее окно для антифлуд/антибрутфорс защиты |
| `admin_audit_log` | Аудит действий администратора через бота |

Она не содержит ни пользователей, ни подписок — только служебное состояние
самого бота.

## Расширение

- **Новая команда/раздел**: добавить обработчик в `worker/src/handlers/`,
  кнопку в `keyboards.ts`, маршрут в `router.ts`.
- **Новое действие API**: добавить `if ($action === '...')` в
  `mod/api/bot.php` или `mod/admin/bot.php` (по аналогии с уже существующими)
  и метод в `worker/src/qmodsApi.ts`.
- **Push-уведомления по новому событию**: вызвать `notify_user_event()` /
  `notify_broadcast_event()` из `mod/includes/bot_notify.php` в нужном месте
  сайта — cron воркера подхватит их автоматически, без изменений в боте.
- **Интеграция с мобильным приложением**: `action=devices` уже возвращает
  массив (не одно устройство) и опциональные поля `name`/`android_version` —
  как только приложение начнёт их передавать на сайт, бот покажет их без
  каких-либо изменений в коде.

## Важное замечание по безопасности

При анализе присланного архива сайта в нескольких файлах (например,
`includes/telegram.php`) обнаружены захардкоженные реальные токен бота и
пароль/хеши администратора. Эти значения **не переносились** ни в один
файл этого проекта — везде используются плейсхолдеры и секреты воркера.
Рекомендуется:
1. Перевыпустить Telegram-токен через @BotFather (`/revoke`), если архив
   когда-либо мог покинуть доверенный контур.
2. Сгенерировать новые `BOT_API_TOKEN_HASH` для обоих файлов (см.
   `php-api/INTEGRATION.md`), а не переиспользовать значения из старых
   бэкапов.
