# QMods Telegram Bot

Telegram-бот для сервиса QMods, работающий как дополнительный канал
управления существующим личным кабинетом **qmods.ru/mod**. Бот не заводит
отдельную базу пользователей/подписок/устройств — он читает и изменяет те
же данные, что и кабинет, через два защищённых JSON API на самом сайте.

Хостинг бота — **Cloudflare Workers** (не классический PHP-хостинг с cron):
логика бота выполняется как serverless-воркер на TypeScript, а всё
взаимодействие с данными QMods идёт по HTTPS в PHP-эндпоинты сайта.

## Архитектура

```
┌─────────────┐   webhook (HTTPS)   ┌────────────────────────┐   HTTPS + токен   ┌───────────────────────┐
│  Telegram    │ ──────────────────▶ │ Cloudflare Worker      │ ─────────────────▶ │ qmods.ru               │
│  (пользо-    │ ◀────────────────── │ (telegram-bot/worker)  │ ◀───────────────── │ mod/api/bot.php         │
│  ватели)     │   sendMessage       │                         │   JSON             │ mod/admin/bot.php       │
└─────────────┘                     │  D1: состояния диалогов,│                    │ (читают/пишут           │
                                     │  рейт-лимиты, аудит-лог │                    │  data/users.json,       │
                                     │  Cron Trigger: доставка │                    │  data/notifications.json)│
                                     │  отложенных уведомлений │                    └───────────────────────┘
                                     └────────────────────────┘
```

- **`worker/`** — сам бот (Cloudflare Worker, TypeScript). Единственное, что
  нужно задеплоить на Cloudflare.
- **`php-api/`** — дополненные версии двух уже существовавших на сайте
  файлов (`mod/api/bot.php`, `mod/admin/bot.php`) + один новый файл-помощник
  (`mod/includes/bot_notify.php`). Их нужно один раз загрузить на qmods.ru.
  Подробности — в `php-api/INTEGRATION.md`.
- **`API.md`** — полный контракт обоих API (какие запросы делает бот, какие
  ответы ожидает).

Почему так: по условию задачи бот обязан работать поверх существующей
системы пользователей QMods, а не поверх своей копии. Cloudflare Workers не
может напрямую читать файлы/БД на обычном PHP-хостинге, поэтому единственный
безопасный способ — HTTPS API с токеном, который сайт уже частично имел
(`mod/api/bot.php`, `mod/admin/bot.php` существовали и раньше) — этот
проект его дополняет, а не изобретает заново.

## Функционал

Бот выступает как персонаж — Кира (аниме-маскот QMods, узнаваемая по
фирменным иллюстрациям сайта: фиолетово-чёрная гамма, кот на плече). Она
представляется на `/start` фото и текстом от первого лица, и так же
подписана строка в разделе поддержки. Подробности — «Маскот (Кира)» ниже.

**Пользователь:**
- `/start` — фото Киры + приветствие, определение статуса привязки, главное меню.
  Если аккаунт не привязан — две равноценные кнопки: привязать существующий
  (см. `/link`) или зарегистрироваться сразу в Telegram (см. ниже) — часть
  миграции пользователей с личного кабинета сайта в бота.
- `/link` — привязка аккаунта по одноразовому коду из кабинета (код,
  ограниченный по времени и попыткам — генерируется и хранится на стороне
  сайта, как и раньше).
- «🆕 Зарегистрироваться в Telegram» — создаёт НОВЫЙ аккаунт qmods.ru прямо
  из бота (`handlers/register.ts`, действие `register` в `mod/api/bot.php`):
  спрашивает никнейм, telegram_id привязывается сразу же, без похода на
  сайт и без пароля (см. «Миграция на Telegram-аккаунты» ниже). Подписки по
  умолчанию нет — как при обычной регистрации без оплаты.
- 👤 Профиль — логин, ID, дата регистрации, уровень, ссылка на скачивание
  APK, форма отзыва.
- ⭐ Подписка — тариф, статус, даты, сколько дней осталось; предупреждение,
  если подписка скоро закончится/уже закончилась.
- 📱 Устройства — просмотр и отвязка с подтверждением.
- 🏆 Достижения — уровень (Новичок/Активный/VIP/Легенда), прогресс до
  следующего, каталог из 13 наград с бонусными днями; синхронизация и
  начисление бонусов происходит прямо в боте, не только на сайте
  (мигрировано из `includes/achievements.php`).
- 🎁 Рефералы — реферальный код и ссылка (генерируется при первом
  обращении), счётчик приглашённых.
- 💳 Оплата — история платежей + кнопка «Продлить» на `qmods.ru/subscribe/`.
- 🔔 Уведомления — личные и общие уведомления, отметка прочитанным.
- 🆘 Поддержка — ссылка на `support.php` + чат сообщества.
- Команды `/sub`, `/devices`, `/ach`, `/pay`, `/notif`, `/support`, `/link`
  открывают соответствующий раздел напрямую, без похода через меню — весь
  список виден в поле ввода Telegram (см. «/setup-menu» ниже).
- Успешная привязка аккаунта и успешное продление подписки администратором
  дополнительно отмечаются реакцией (🎉/👍) на само сообщение с кодом/днями —
  мгновенный визуальный отклик через `setMessageReaction`, без лишнего текста.
- **Inline-режим**: `@<имя_бота> ` в любом чате — делится карточкой своей
  подписки или уровня/достижений без открытия бота (`handlers/inline.ts`).
  Требует включения Inline Mode через [@BotFather](https://t.me/BotFather)
  (`/setinline`) — Bot API не даёт включить это программно.

**Администратор** (`/admin`, ID в `ADMIN_TELEGRAM_IDS`):
- статистика (пользователи, активные подписки, привязанные Telegram-аккаунты);
- поиск пользователя по логину, карточка со всеми данными;
- продление/снятие подписки, удаление аккаунта (с подтверждением);
- отправка сообщения конкретному пользователю или рассылка всем;
- «🌐 Вход/регистрация на сайте» — выключатель миграции: одна кнопка,
  переключающая `data/site_auth_gate.json` на сайте (`get_site_auth_gate`/
  `set_site_auth_gate` в `mod/admin/bot.php`) — см. «Миграция на
  Telegram-аккаунты» ниже;
- видит расширенный список команд (`/setup-menu` регистрирует его отдельно
  для каждого ID из `ADMIN_TELEGRAM_IDS` через `BotCommandScopeChat`).

## Миграция на Telegram-аккаунты

Цель — постепенно перевести всех пользователей на аккаунты, полностью
управляемые через бота, и в конце концов отключить собственные вход/
регистрацию на сайте. Три независимые части, каждая работает и без двух
других:

1. **Привязка существующего аккаунта** — `/link` (было всегда) и привязка
   по юзернейму из Android-приложения без Telegram на телефоне (см.
   `android-client/README.md` «Привязка по юзернейму»).
2. **Регистрация нового аккаунта прямо в боте** — «🆕 Зарегистрироваться в
   Telegram» на `/start`, без обращения к сайту вообще. Аккаунт создаётся
   без поля `password` (тот же формат, что у аккаунтов, которые админ
   создаёт через `issue`/create) — вход в такой аккаунт возможен только
   через бота, пока на сайте не реализован отдельный сценарий «войти через
   Telegram» или сброс пароля.
3. **Выключатель входа/регистрации на сайте** — `data/site_auth_gate.json`
   (по умолчанию включено, ничего не меняется без явного действия админа).
   Переключается кнопкой «🌐 Вход/регистрация на сайте» в `/admin`. Не
   требует патча воркера/бота — только `mod/login.php`/`mod/register.php`
   на самом сайте, инструкция в `php-api/INTEGRATION.md` «Выключатель
   входа/регистрации на сайте». Различает два случая: обычный браузер
   (без `device_id`) отправляется в бота, а **старое** Android-приложение
   (у него нет кода для привязки через бота — оно умеет входить только
   через `login.php`/`register.php`, поэтому обычный «мин. версия
   приложения» через `/device/subscription` для него не работает, оно
   вообще не стучится к воркеру) видит «обновите приложение»; если при
   этом у него уже был активный аккаунт — сессия не сбрасывается, и сразу
   же показывается код/диплинк привязки Telegram, чтобы человек успел
   привязаться, ещё сидя в старой версии.

Ни один из трёх пунктов не ломает уже привязанные аккаунты и не требует
включения остальных двух — можно, например, только добавить регистрацию в
боте, оставив сайт как есть неограниченно долго.

**Push-уведомления** (Cron Trigger раз в 5 минут): оплата, окончание
подписки (уже автоматизировано на сайте, см. `reminders.php`), сообщения
администратора, новости — доставляются даже если пользователь не открывал
бота в момент события.

## Скрытые ошибки → алерт в Telegram

Любое необработанное исключение — в `fetch`, в обработке апдейта из
вебхука, в `scheduled` (cron) или в `POST /app/api` Mini App — раньше
уходило только в `console.error`, то есть было видно исключительно тому, кто
в этот момент смотрит `wrangler tail`. Теперь оно долетает до администраторов
в Telegram (`src/errorReport.ts`):

- Сообщение содержит место (`fetch POST /webhook`, `callback adm:issue`,
  `webapp/api action=me` и т.п.), тип и текст ошибки, первые строки стека.
- Дедупликация — одинаковая ошибка (по месту + типу/сообщению + верхнему
  кадру стека, хешировано) шлётся не чаще раза в 10 минут, вне зависимости
  от того, сколько раз она реально произошла; счётчик повторов при этом
  копится и показывается в сообщении. Состояние — новая таблица D1
  `error_alerts`, см. «SQL» ниже.
- Сам механизм алертов никогда не бросает исключение — сбой D1 или Bot API
  внутри `reportError()` тихо логируется и не аффектит основной запрос.

## Mini App

Кнопка «🖥 Открыть в Mini App» в главном меню открывает `GET /app` —
тот же функционал в виде нативного полноэкранного интерфейса внутри
Telegram: вкладки Профиль (+ скачать APK, отзыв), Подписка, Устройства,
Награды (уровень, прогресс, достижения, рефералы), Оплата, Уведомления, а
для непривязанного аккаунта — экран ввода кода. Тема (тёмная/светлая)
подхватывается автоматически через `--tg-theme-*` CSS-переменные, которые
Telegram сам подставляет.

Для администраторов (`ADMIN_TELEGRAM_IDS`) появляется дополнительная
вкладка «🛠 Админ» — тот же `isAdmin()`, что и в чат-боте, просто
`action=me` в `webapp/api.ts` дополнительно возвращает `is_admin`, и
вкладка показывается только если он true. Внутри: статистика с графиком
выручки за 14 дней (SVG, без сторонних библиотек), список всех
пользователей с мгновенным фильтром по нику (загружается один раз, фильтр
работает на клиенте — без запроса на каждое нажатие клавиши, в отличие от
пошагового поиска в чат-боте), карточка пользователя с продлением/снятием
подписки/удалением/личным сообщением, и форма рассылки всем. Каждое
admin_*-действие в `webapp/api.ts` отдельно проверяет `isAdmin()` — доступ
к чужим данным через Mini App невозможен, даже если ссылку на `/app`
передать не-администратору.

- Один файл, без сборки и фреймворков (`worker/src/webapp/page.ts`) —
  разметка, стили и JS-логика в одном месте, отдаётся как обычный HTML.
- Бэкенд — один эндпоинт `POST /app/api`, авторизация через Telegram
  `initData` (см. «Безопасность» ниже), логика полностью переиспользует
  `QmodsUserApi` — та же авторизация к `mod/api/bot.php`, что и у чат-бота.
- Работает независимо от чат-версии: можно продолжать пользоваться только
  кнопками, Mini App — альтернативный, а не обязательный интерфейс.
- Требует `PUBLIC_URL` в `wrangler.toml` (origin этого же воркера, без
  пути) — если оставить пустым, кнопка просто не показывается.
- Регистрировать домен через @BotFather не нужно — это требование только
  для Login Widget, а не для `web_app`-кнопок в инлайн-клавиатуре или для
  Chat Menu Button (обе используют `PUBLIC_URL` напрямую).
- Кроме кнопки в меню, `/setup-menu` (см. «Установка») ставит и постоянную
  **Chat Menu Button** — иконку рядом со строкой ввода сообщения, которая
  открывает Mini App в один тап из любого момента переписки, а не только из
  главного меню.

## Авторизация приложения через бота

Отдельный протокол для нативного Android-приложения QMods — вход через
Telegram-бота вместо пароля/сессии на сайте, плюс проверка подписки. Полный
клиентский код (на smali, для вклейки в уже собранный APK без исходников) —
`android-client/README.md`; здесь только серверная часть.

1. Приложение: `POST /device/pair/start` (воркер) → короткий код + ссылка
   `t.me/<бот>?start=devicelink_<CODE>` (D1-таблица `device_pairings`,
   код живёт 10 минут).
2. Приложение открывает эту ссылку — Telegram открывает бота.
3. Пользователь уже привязан к qmods.ru через обычный `/link`? Бот
   (`handlers/devicePair.ts`) подтверждает код, выдаёт `device_token`
   (D1-таблица `device_tokens`) и зеркалит его в `device_id` на qmods.ru
   (действие `device_register` в `mod/api/bot.php`) — поэтому приложение
   появляется в разделе «Устройства» бота/кабинета как обычное устройство.
4. Приложение поллит `GET /device/pair/status?code=` до получения токена,
   сохраняет его локально.
5. Дальше при каждом холодном старте **и каждые ~90 сек, пока приложение
   открыто** — `GET /device/subscription?token=&version_code=` — воркер
   резолвит токен в username и спрашивает `mod/api/bot.php` (действие
   `device_subscription`) от своего собственного бот-токена. Ответ несёт
   не только `subscription`, но и необработанные админ-уведомления
   (`notifications`) и гейт принудительного обновления (`force_update`) —
   см. `android-client/README.md` «Проверка во время использования».
   Приложение никогда не видит ни пароль/сессию сайта, ни бот-токен
   воркера — только свой `device_token`.
6. Отвязка устройства через бота/Mini App (штатное `device_remove`) заодно
   удаляет строку из D1 `device_tokens` (`revokeDeviceToken()` в
   `worker/src/db.ts`) — токен в приложении перестаёт работать, следующая
   проверка вернёт `onError("not_paired")` и уводит на экран привязки.

Все три маршрута анонимны (без initData/Telegram-контекста, в отличие от
Mini App), поэтому у каждого свой рейт-лимит через `checkRateLimit()`
(по IP для `pair/start`, по коду для `pair/status`, по токену для
`subscription`).

## Оплата через ЮMoney

Покупка подписки прямо в боте — кнопками в чате и в Mini App («💳 Оплата»
→ выбор тарифа). Это **классический кошелёк ЮMoney** (Quickpay-форма +
HTTP-уведомления), не эквайринг ЮKassa — не нужен ни магазин-аккаунт, ни
API-ключ, только номер счёта и один секрет из настроек кошелька.

1. **Приложение/бот**: `plans` (уже существовавшее, но не подключённое
   действие `mod/api/bot.php`) отдаёт список тарифов → пользователь
   выбирает → `worker/src/db.ts` создаёт строку в D1 `payment_orders`
   (`id` станет ЮMoney-параметром `label`) → `worker/src/yoomoney.ts`
   строит Quickpay-ссылку (`https://yoomoney.ru/quickpay/confirm.xml?...`)
   → бот показывает кнопку «💳 Оплатить» (`url`) и «🔄 Проверить оплату»
   (`callback_data`, на случай если возврат/вебхук задержится).
2. **Пользователь** платит на странице ЮMoney (картой или с кошелька) и
   возвращается в бота по `successURL` (`t.me/<bot>?start=paid_<orderId>`).
3. **ЮMoney** шлёт HTTP-уведомление на `POST /pay/yoomoney/webhook`
   (настраивается в кошельке, см. ниже) — единственная защита этого
   эндпоинта — проверка `sha1_hash` по документированной ЮMoney формуле
   (`worker/src/yoomoney.ts verifyNotificationSignature`), никаких других
   заголовков/аутентификации у ЮMoney для уведомлений нет. Без верной
   подписи запрос отклоняется (`403`), без проверки суммы и `unaccepted`
   ничего не засчитывается.
4. **Воркер** атомарно (`markPaymentOrderPaid`, guard `WHERE status =
   'pending'`) помечает заказ оплаченным — защита от повторной выдачи дней
   при повторной доставке того же уведомления (ЮMoney шлёт его, пока не
   получит `200`) — и вызывает `record_payment` в `mod/admin/bot.php`:
   продлевает подписку и пишет запись в историю платежей. Дальше воркер
   сразу подтверждает оплату в чате и глушит дублирующее уведомление от
   5-минутного крона через `ack_telegram_push` (см. `API.md`
   `record_payment`).
5. **Mini App** после открытия ссылки оплаты опрашивает `pay_status`
   каждые 3 сек (до ~1 минуты) — отражает статус без необходимости
   покидать/перезаходить в приложение.

### Настройка

1. Зайдите в настройки своего кошелька на yoomoney.ru → «Для бизнеса» /
   «HTTP-уведомления» — включите их и укажите URL:
   `https://<ваш-воркер>/pay/yoomoney/webhook` (тот же `PUBLIC_URL`, что и
   для Mini App). Там же задаётся **секрет уведомлений** — скопируйте его.
2. Секреты воркера:
   ```bash
   wrangler secret put YOOMONEY_NOTIFICATION_SECRET   # секрет из шага 1
   ```
3. В `worker/wrangler.toml` замените `YOOMONEY_WALLET` на номер своего
   счёта (не секрет, обычная переменная).
4. Задеплойте PHP (`mod/admin/bot.php` — новое действие `record_payment`)
   и Worker (`wrangler deploy`).

Никаких изменений на самом сайте qmods.ru (`subscribe/notify.php` и т.п.)
не требуется — весь этот поток целиком внутри бота/воркера, отдельно от
существующей site-side оплаты и её админ-алерта (см. `php-api/INTEGRATION.md`
«Алерт админу об оплате» — то отдельный путь для оплат через сам сайт).

## Безопасность

- **Webhook**: Telegram шлёт заголовок `X-Telegram-Bot-Api-Secret-Token`
  (задаётся при `setWebhook`), воркер сверяет его константным по времени
  сравнением до разбора апдейта — `src/security.ts`.
- **API-токены**: два независимых bcrypt-хешированных токена
  (пользовательский/админский), сверяются на сайте через `password_verify()`.
  Сами токены — только в секретах воркера (`wrangler secret put`), никогда
  не попадают в код/репозиторий.
- **Рейт-лимит**: код `/link` ограничен на двух уровнях — в воркере (D1,
  6 попыток / 10 мин на чат) и на сайте (`data/bot_link_attempts.json`,
  8 попыток / 15 мин на telegram_id).
- **Mini App**: каждый запрос к `POST /app/api` обязан нести заголовок
  `Authorization: tma <initData>`. `initData` проверяется по официальной
  схеме Telegram (`worker/src/webapp/validate.ts`) — HMAC-SHA256 на секрете,
  производном от `TELEGRAM_BOT_TOKEN`, плюс проверка `auth_date` (не старше
  24 часов, защита от replay). `telegram_id` берётся только из
  провалидированной подписи — Mini App физически не может подставить чужой
  ID в запросе.
- **Права администратора**: единая проверка `isAdmin()` перед любым
  `adm:*`-действием и при обработке текстового ввода в админ-режиме — даже
  если состояние диалога в D1 каким-то образом переживёт потерю прав.
- **Логирование**: действия администратора пишутся в D1
  (`admin_audit_log`) независимо от `data/actions.log` на сайте; ошибки
  воркера видны через `wrangler tail`.
- Входные данные everywhere проходят через типизированные API-клиенты и
  HTML-экранирование (`esc()`) перед вставкой в сообщения — защита от
  инъекции разметки через логин/название тарифа и т.п.

## Установка и деплой

### 1. PHP-часть (qmods.ru)

См. `php-api/INTEGRATION.md` — какие файлы куда положить, как сгенерировать
токены, где (опционально) добавить одну строку для проактивных уведомлений
об оплате.

### 2. Telegram-бот

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите токен.
2. `cd telegram-bot/worker && npm install`
3. `wrangler d1 create qmods-telegram-bot` — скопируйте `database_id` в
   `wrangler.toml`.
4. `npm run db:init` — накатывает `schema.sql` на созданную D1-базу.
5. Секреты:
   ```bash
   wrangler secret put TELEGRAM_BOT_TOKEN
   wrangler secret put TELEGRAM_WEBHOOK_SECRET       # любая случайная строка, напр. `openssl rand -hex 32`
   wrangler secret put QMODS_BOT_API_TOKEN           # токен для mod/api/bot.php
   wrangler secret put QMODS_ADMIN_BOT_API_TOKEN     # токен для mod/admin/bot.php
   ```
6. Проверьте/поправьте `vars` в `wrangler.toml` (`QMODS_API_BASE`,
   `ADMIN_TELEGRAM_IDS` и т.д.).
7. `npm run deploy` — публикует воркер, выводит URL вида
   `https://qmods-telegram-bot.<account>.workers.dev`.
8. Если URL воркера отличается от того, что уже стоит в `PUBLIC_URL` —
   поправьте (без пути, без слэша на конце) и передеплойте, иначе не
   покажется кнопка Mini App и не будут отправляться фото Киры.

### 3. Подключение webhook

Самый простой способ — встроенный служебный маршрут воркера:

```
GET https://<worker-url>/setup-webhook?token=<TELEGRAM_WEBHOOK_SECRET>
```

Откройте эту ссылку один раз в браузере (или `curl`) — воркер сам вызовет
`setWebhook` с правильным URL и секретом. Убедиться, что всё подключилось:

```bash
curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"
```

Если бот уже был подключён раньше (до появления inline-режима) — откройте
`/setup-webhook` ещё раз: `setWebhook` перезаписывает `allowed_updates`
целиком, а без повторного вызова Telegram продолжит не присылать
`inline_query`-апдейты, даже если Inline Mode включён у @BotFather.

### 4. Cron (доставка отложенных уведомлений)

Уже настроен в `wrangler.toml` (`[triggers] crons = ["*/5 * * * *"]`) —
отдельно ничего запускать не нужно, `wrangler deploy` регистрирует триггер
автоматически. При необходимости поменяйте частоту там же.

### 5. Персона бота (Кира) — необязательно, но рекомендуется

```
GET https://<worker-url>/setup-profile?token=<TELEGRAM_WEBHOOK_SECRET>
```

Тот же принцип, что и `/setup-webhook` — открыть один раз. Задаёт имя бота
и оба описания (`setMyName`/`setMyDescription`/`setMyShortDescription`)
текстом от лица Киры. Аватар бота у Bot API нет метода задать программно —
это по-прежнему только вручную, через [@BotFather](https://t.me/BotFather):
`/setuserpic` → выбрать бота → отправить `worker/public/img/kira-hero.jpg`.

### 6. Команды и Chat Menu Button — необязательно, но рекомендуется

```
GET https://<worker-url>/setup-menu?token=<TELEGRAM_WEBHOOK_SECRET>
```

Регистрирует список команд «/» (свой для всех и расширенный — с `/admin` —
персонально для каждого ID из `ADMIN_TELEGRAM_IDS`), а если `PUBLIC_URL`
уже настроен — ещё и ставит Chat Menu Button, открывающую Mini App прямо из
строки ввода. Безопасно повторять сколько угодно раз (например, после
изменения `ADMIN_TELEGRAM_IDS`).

Чтобы заработал inline-режим (`@<бот> ` в любом чате), его нужно один раз
включить вручную через [@BotFather](https://t.me/BotFather) → выбрать бота →
`/setinline` → задать любую подсказку-placeholder. Это отдельный переключатель,
Bot API не может включить его сам.

## Маскот (Кира)

Изображения — `worker/public/img/` (обслуживаются Workers Assets
напрямую, минуя код воркера; путь `/img/<файл>` = `worker/public/img/<файл>`
без изменений). Все — сжатые WebP (~640px, ~80–115 КБ) плюс один JPEG для
Telegram `sendPhoto` (WebP там не всегда корректно рендерится как фото,
JPEG — надёжный вариант).

| Файл | Где используется |
|---|---|
| `kira-hero.jpg` / `kira-hero.webp` | Фото в `/start` (чат-бот) и экран привязки в Mini App |
| `kira-loading.webp` | Стартовый экран загрузки Mini App |
| `kira-empty.webp` | Пустое состояние (устройство не привязано) |
| `kira-success.webp`, `kira-error.webp`, `kira-support.webp` | Заготовлены, пока не задействованы — см. «Расширение» |

Персона включается только через `PUBLIC_URL` (см. выше) — без него фото
просто не отправляются/не показываются, ничего не ломается.

## SQL / хранилище данных

qmods.ru хранит пользователей, подписки, устройства и уведомления в
файлах `data/*.json` (см. `includes/bootstrap.php` на сайте) — это
**существующая архитектура**, новых MySQL-таблиц под неё создавать не
нужно и не следует (задача явно требует не плодить отдельную базу).

Единственное новое хранилище — **Cloudflare D1** (`worker/schema.sql`),
и оно принадлежит исключительно боту:

| Таблица | Назначение |
|---|---|
| `bot_state` | Состояние диалога чата (например, «ждём код /link») |
| `rate_limits` | Скользящее окно для антифлуд/антибрутфорс защиты |
| `admin_audit_log` | Аудит действий администратора через бота |
| `error_alerts` | Дедупликация/cooldown алертов о скрытых ошибках (см. выше) |
| `device_pairings` | Короткоживущие коды привязки приложения через бота |
| `device_tokens` | Долгоживущие device_token → username (авторизация приложения) |
| `payment_orders` | Попытки оплаты через ЮMoney — `id` = Quickpay `label`, `status` защищает от повторной выдачи дней (см. «Оплата через ЮMoney») |

Она не содержит ни пользователей, ни подписок — только служебное состояние
самого бота.

Если воркер уже был развёрнут раньше (до появления `error_alerts`) — накатите
обновлённую схему на существующую базу:

```bash
wrangler d1 execute qmods-telegram-bot --file=./schema.sql --remote
```

`CREATE TABLE IF NOT EXISTS` делает это безопасным для повторного запуска —
существующие таблицы не трогаются.

## Расширение

- **Новая команда/раздел**: добавить обработчик в `worker/src/handlers/`,
  кнопку в `keyboards.ts`, маршрут в `router.ts`.
- **Новое действие API**: добавить `if ($action === '...')` в
  `mod/api/bot.php` или `mod/admin/bot.php` (по аналогии с уже существующими)
  и метод в `worker/src/qmodsApi.ts`.
- **Push-уведомления по новому событию**: вызвать `notify_user_event()` /
  `notify_broadcast_event()` из `mod/includes/bot_notify.php` в нужном месте
  сайта — cron воркера подхватит их автоматически, без изменений в боте.
- **Интеграция с мобильным приложением**: `action=devices` уже возвращает
  массив (не одно устройство) и опциональные поля `name`/`android_version` —
  как только приложение начнёт их передавать на сайт, бот покажет их без
  каких-либо изменений в коде.

## Важное замечание по безопасности

При анализе присланного архива сайта в нескольких файлах (например,
`includes/telegram.php`) обнаружены захардкоженные реальные токен бота и
пароль/хеши администратора. Эти значения **не переносились** ни в один
файл этого проекта — везде используются плейсхолдеры и секреты воркера.
Рекомендуется:
1. Перевыпустить Telegram-токен через @BotFather (`/revoke`), если архив
   когда-либо мог покинуть доверенный контур.
2. Сгенерировать новые `BOT_API_TOKEN_HASH` для обоих файлов (см.
   `php-api/INTEGRATION.md`), а не переиспользовать значения из старых
   бэкапов.
